# JOINT-WORK-SPECKIT-001

Status: **preregistered; zero-provider scripted arm only**

This experiment asks whether OpenLine can sit underneath GitHub Spec Kit rather than inventing its own planning layer.

```text
GitHub Spec Kit
constitution + spec + plan + tasks
              ↓
        owner freezes them
              ↓
      OpenLine Wallet
     task-scoped authority
         ↙            ↘
      T101            T201
     producer         receiver
         ↓
   revoke worker A
         ↓
 successor gets T102
         ↘            ↙
          Airlock
   protected composition
              ↓
          survives
```

No live model provider is used in this arm. Provider spend is fixed at **$0**.

## External substrate

The experiment pins GitHub Spec Kit at:

```text
d848fb4e18f44640ad6b42e60a280551ee90cdce
```

It also pins the exact Git blob IDs of the upstream constitution, specification, plan, and task templates. CI checks out that commit read-only and verifies those exact template blobs before the experiment runs.

The owner-authored project artifacts use Spec Kit's native paths and structure:

```text
.specify/memory/constitution.md
specs/001-signed-webhook/
├── spec.md
├── plan.md
├── tasks.md
└── contracts/
    └── webhook.md
```

They are deliberately not claimed to have been generated by the Spec Kit CLI. This arm tests the pinned Spec Kit artifact model and task conventions as an external planning substrate. It does not reproduce `/speckit.*` agent reasoning.

The frozen Spec Kit artifact root is:

```text
e6bbaf6901a2ae50e6763f593402224bbda5fad3d8b12b51920dada07e6d8c50
```

## Frozen task split

`tasks.md` uses Spec Kit's `[P]` convention for parallel work.

```text
T101 [P] [US1]  producer canonicalization/signing checkpoint
T201 [P] [US2]  receiver verification/replay protection
T102     [US1]  producer continuation after accepted T101 checkpoint
T301     [US3]  owner-only protected Airlock composition
```

T101 and T201 touch different implementation files and start from the same frozen project definition.

```text
Worker A: src/producer.py
Worker B: src/receiver.py
```

The workers cannot modify `.specify/**`, `specs/**`, `tests/**`, or `.airlock/**`.

## Authority

OpenLine Wallet binds worker authority to the frozen Spec Kit root plus exact task IDs.

Worker A initially receives T101 and T102. Worker B receives only T201. A deliberate Worker A → T201 authorization attempt must return `STOPPED / ACTION_OUTSIDE_MANDATE`.

After Worker A reaches the T101 checkpoint, the owner signs a handoff containing the Spec Kit root digest, exact checkpoint commit/blob digest, the T101 gate receipt hash, the explicit unresolved T102 task, and Worker B's accepted branch checkpoint as public project state.

Worker A is then revoked. Its next T102 action must return:

```text
STOPPED
MANDATE_REVOKED
```

A new subject receives successor authority for T102 bound to the signed handoff digest and continues from the exact T101 checkpoint.

## Independent acceptance

Spec Kit defines the project, but Spec Kit convergence is not the final judge in this proof.

Airlock current pinned source owns the final protected executable acceptance rule. Worker-local producer and receiver checks must pass, but the combined candidate survives only if:

```text
python -B tests/test_convergence.py
```

passes under Airlock while all frozen project and judge files remain unchanged.

That distinction is intentional:

```text
Spec Kit defines what the project is supposed to become.
Wallet defines which worker may do which task.
Airlock defines which combined implementation is allowed to survive.
```

## Preregistered negative control

The valid producer must preserve the exact caller nonce.

The negative producer replaces every caller-supplied nonce with the valid constant:

```text
nonce-fixed-0001
```

and re-signs the resulting payload. The producer-local check deliberately validates nonce shape and signature correctness, not caller-value preservation, so the broken producer remains locally green. The receiver-local check also remains green.

The protected composition test sends two different caller nonces. Under the broken producer they collapse to one receiver nonce, so the second request becomes a replay. Airlock must reject the combined candidate.

If that candidate survives, the experiment fails.

## Terminal scripted success

The arm passes only if all of the following hold:

- the pinned Spec Kit source/template blobs verify;
- frozen Spec Kit artifacts keep their preregistered digests;
- T101 and T201 make measured overlapping progress in separate worktrees;
- Wallet allows only each worker's task scope;
- T101 reaches a valid checkpoint while T102 remains genuinely unresolved;
- Worker A revocation stops its next T102 action;
- the successor continues from the exact checkpoint under handoff-bound T102 authority;
- the locally-green fixed-nonce composition is rejected by Airlock;
- the valid composition passes the same protected Airlock gate;
- provider calls and provider spend remain zero.

Expected verdict:

```text
SCRIPTED_SPECKIT_ARM_PASS_LIVE_NOT_RUN
```

If PASS, the narrow earned claim is:

> In a zero-provider scripted fixture using a pinned GitHub Spec Kit project definition, Wallet enforced separate task authority and revocation/successor handoff, while Airlock rejected a locally-green cross-task requirement violation and accepted the valid combined implementation.

That claim does not establish live Claude/Codex behavior, Spec Kit CLI generation, provider replacement in production, or general software correctness.

Stop after the scripted result. A live-provider arm requires a separate decision after this proof is green.
